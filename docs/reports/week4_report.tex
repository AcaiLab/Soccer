\section*{Project Overview}
Our project investigates how vision-language models can identify important events in soccer match
videos and generate natural-language commentary describing those events. Our main goal is to
determine how accurately soccer events can be identified from video, and how those events can be
used to generate accurate commentary for different audiences, including casual viewers, expert fans,
and people with low vision. The project builds on the SoccerReplay-1988 dataset~[5] and existing
baseline methods for soccer event classification.

\section*{Where Our Last Report Left Off}
Last week we reported no results on real data. The supervised evaluation was built and tested on
synthetic features, and the match videos and features were still being re-obtained. Our video
processing ran on personal machines, on the CPU, and each step was slow.

\section*{Current Progress: Migrating the Data and Compute to the NVIDIA Server}
This week we focused on moving the data and all heavy computation from our personal machines to the
professor's NVIDIA GPU server. In summary:

\begin{enumerate}[noitemsep]
  \item \textbf{Access.} We connect to the server over SSH with a key pair authorized by the professor.
        The private key stays on one computer and is never shared or stored in the project.
  \item \textbf{Environment.} We wrote a setup script that builds an isolated Python environment on the
        server with pinned dependencies and no administrator rights. Credentials are kept in a settings file
        readable only by us, never in the code. The project code is deployed to the server from the
        cleaned \texttt{cleanup/dino-contrastive} branch (kept locally, not yet pushed).
  \item \textbf{Annotations.} The match annotation files (JSON) were copied to the server, 65 matches of
        the English Premier League 2021--22 season.
  \item \textbf{Videos.} The videos sit in a password-protected shared folder behind an API that issues
        access tokens lasting only four hours. We replaced the manual token step with a one-time
        authorization that renews tokens automatically, so downloads run unattended. The server downloads each
        match (about 1.2\,GB per match) straight from the shared folder, extracts the frames around each
        annotated event, and deletes the video, so only one match is on disk at a time. Three downloads run in
        parallel; 35 matches took under an hour.
  \item \textbf{Frames and features.} For the 65 matches (130 halves) this produced about 267{,}000 frames,
        roughly 23\,GB, which are encoded on the server with the frozen DINOv2 model. The encoding is cached
        per half, so adding matches only encodes the new ones. The GPU is shared with other users and is often
        full, so the code checks for free memory and falls back to the CPU automatically.
  \item \textbf{Checking the migrated data.} We verified that a fresh copy of the code, run with one command
        on a clean data folder, reproduces identical frames. Validating the data this way also revealed
        problems in the older frame-extraction code (events cut from the wrong half's video, and frames
        drifting from the video clock in some recordings), which we fixed; the details are in the attached
        conversation.
\end{enumerate}

Experiments run on this setup, including the supervised and contrastive results, will be reported
separately.

\section*{Challenges and Issues}
\textbf{Short-lived access tokens.} Dropbox tokens expired every four hours, which interrupted long downloads.
The one-time authorization fixed this.

\textbf{A shared GPU.} Another user's job often holds almost all of the GPU memory, so some of our steps run on
the CPU and take hours.

\textbf{Data volume.} Each match is about 1.2\,GB of video and 0.4\,GB of frames, so videos are deleted after
extraction and everything is resumable if a run stops.

\section*{Next Steps}
\begin{enumerate}[noitemsep]
  \item Sweep the contrastive embedding size (64, 128, 256, 512), compared on held-out data.
  \item Add class-balanced anchor sampling, then compare random and semi-hard negatives by per-class F1.
  \item Hold out a second league-season or a different competition, which needs new videos on the server.
  \item Only then scale beyond 65 matches, and revisit temporal models against the final baseline.
\end{enumerate}
