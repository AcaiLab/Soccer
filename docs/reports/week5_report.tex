\section*{Project Overview}
Our project investigates how vision-language models can identify important events in soccer match
videos and generate natural-language commentary describing those events. Our main goal is to
determine how accurately soccer events can be identified from video, and how those events can be
used to generate accurate commentary for different audiences, including casual viewers, expert fans,
and people with low vision. The project builds on the SoccerReplay-1988 dataset~[5] and existing
baseline methods for soccer event classification.

\section*{Where Our Last Report Left Off}
Last week we moved the data and all heavy computation from our personal machines to the professor's
NVIDIA GPU server.

\section*{Current Progress: Working on the Server and Cleaning Up the Pipeline}
This week we continued working on the server and cleaned up the pipeline code on our
\texttt{cleanup/dino-contrastive} branch, a cleaned version of the \texttt{dino-contrastive-pipeline}
branch.
\begin{enumerate}[noitemsep]
  \item \textbf{Evaluation code.} Every classifier report now gives balanced accuracy next to macro-F1 and
        accuracy, and every classifier saves its predictions for each test event, so any score can be
        recomputed and errors can be inspected event by event.
  \item \textbf{Splits.} We set up 5-fold cross-validation by whole match over our 65 Premier League
        2021--22 matches (45 training, 7 validation and 13 test matches per fold), so that every match is a
        test match exactly once and tuning uses only each fold's validation matches.
  \item \textbf{Label documentation.} A script now writes out which labels are kept and which are excluded,
        with event counts per split. Four labels are excluded (185 events): two broadcast graphics and two
        scraper artefacts. The remaining 22 event types hold 4,337 events.
  \item \textbf{Reproducibility on the server.} A fresh copy of the code, run with one command on a clean
        data folder, reproduces the same frames as our main run.
  \item \textbf{Planning the next data.} We listed what the shared video folder holds: all 1,988 matches,
        including 552 Premier League matches across seven seasons, which we can add in stages.
\end{enumerate}

\section*{Challenges and Issues}
\textbf{Data problems found during cleanup.} Checking the data showed that the older frame extraction
had cut some events from the wrong half's video, and that some recordings state a wrong frame rate, so
frames drifted away from the video's own clock. Both are now fixed.

\textbf{Model selection.} Our code still chooses models on validation accuracy, while macro-F1 is our main
metric. We will switch it to macro-F1.

\section*{Next Steps}
\begin{enumerate}[noitemsep]
  \item Report baseline results on real data, with macro-F1 and balanced accuracy.
  \item Switch model selection to validation macro-F1.
  \item Add more Premier League seasons in stages, which also makes a whole-season hold-out possible.
  \item Sweep the contrastive embedding size (64, 128, 256, 512) and add class-balanced anchor sampling.
\end{enumerate}
